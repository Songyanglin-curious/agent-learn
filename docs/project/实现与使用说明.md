# 实现与使用说明

## 运行组成

本说明针对 DSH Bundle，包名 dsh-agent-learn，插件标识 agent-learn。cordis.patch.yml 将插件挂入宿主；必需注入 agents、tools、systemPrompt。文件读写使用原 Agent 的现有工具，插件没有独立模型、数据库或文件维护后台。

| 位置 | 职责 |
| --- | --- |
| src/index.mjs | 注册教学路由、agent_learn_rules 工具和 agent/turn-stopping 监听器 |
| src/workspace.mjs | 验证当前 cwd 的启用标记和学习根索引 |
| src/rules.mjs | 包内默认规则定位、显式自定义补齐、完整依赖回退与指令生成 |
| rules/ | 默认规则的唯一源，包含专题规划规则和独立范例 |
| scripts/build.mjs | 将运行代码与规则复制到 lib/defaults，构建产物独立于仓库外文件 |
| scripts/pack.mjs | 使用 npm 标准打包链生成 TGZ 与 SHA-256 清单 |
| tests/ | 公开事件接口、规则文件保护及真实 Cordis/DSH 服务测试 |

普通教学通过简短系统提示路由到 teaching；此路由在插件加载后全局可见，但明确排除普通一次性问答和非学习任务，不全局注入完整规则。完整规则由原 Agent 按需读取。

## 工作区边界

自动检查要求当前会话 header.cwd 为绝对路径，且目录内有有效 `.agent-learn.json`（version=1、enabled=true）和 index.md 文件。不向父目录搜索，不由配置强绑所有聊天，不在 Hook 中初始化。每次准备投递提醒时重新检查工作区标记，停用在下一次检查时生效。

标记仅用于显式启用，不保存学习数据。根索引导航领域，领域计划导航到独立专题计划。进度保存当前位置、接续点及已完成、暂挂或跳过的阶段，也可链接到能确认状态的成果。阶段总结与专题总结按需复用或新建成果文件，具体职责与组织方式由包内 spec 定义。

## 规则工具

- init：供用户明确要求建立持续学习时读取初始化规则，工具不直接创建学习工作区。
- teaching：建立或恢复专题计划，按阶段组织教学、补缺和综合。新建或结构性修订计划时，读取同目录的 [规划规则](../../rules/planning.md)，首次使用时对照[规划范例](../../rules/planning-example.md)。正常接续读取已有专题计划和进度。每轮进入专题教学时调用一次，作为本轮允许自动补漏的信号。
- maintain：显式进行状态和成果补漏。
- info：返回当前规则目录和三类操作规则的实际路径。

规则目录优先级为插件 rulesDir、AGENT_LEARN_RULES_DIR、DSH 安装包内 defaults。默认只读包内规则，升级后使用新版默认规则。显式自定义目录会补齐缺失的规则与范例，已有用户文件保留。自定义依赖不可读时整套回退包内 defaults。旧版 ~/.agent-learn/dsh 可按需通过显式配置继续使用。

用户规则为自定义版本，不随源码发布自动升级。工具会返回实际 cwd（可取得时）和规则路径；规则路径不等于学习数据目录。

## 轮次结束检查

使用 DSH 的 agent/turn-stopping serial 事件。插件用宿主 `turnBoundaryOf` 的 `lastTurn` 登记本轮教学，未登记的轮次直接放行。对已登记的轮次按 Agent 和 turn 去重，跳过 origin=subagent 或 delegationDepth>0。带 parentSessionId 的普通 fork 可按本轮自己的调用触发补漏。

首次进入可自动补漏的专题教学时，`teaching` 把带标题、版本和来源路径的 `maintain.md` 正文放在工具结果中。工具和 Hook 都通过 DSH 的 `session.deriveMessages()` 检查当前有效会话历史。正文被压缩移除、自定义规则变更或实际规则路径改变时，下一次检查会补载当前版本。

符合条件时用 agent.steer(createUserMessage(...)) 投递一次补漏指令，消息来源为 kind=agent-learn、form=instructions。提醒按标题和版本引用已有维护规则，保留文件路径供正文不可见时补读。教学轮次内是否有未保存的变化由当前 Agent 判断，有提醒时可能多一次模型续接。

成功调用 init 或 maintain 时跳过同轮提醒。info 只提供路径信息。enabled=false 关闭自动 Hook，工具和轻量路由仍可使用。

取消、卸载或异常不继续投递。监听器和工具由 Cordis 生命周期托管；没有自建定时器和后台异步任务。与其他 Hook 共存时各自去重，可能收到多个插件的提醒；不接管其他插件或跨插件共用“已维护”标记。

## 使用与效果边界

安装、启用和规则编辑步骤见仓库根 README.md，独立 TGZ 同时携带该说明。DSH 0.1.3 的轮末指令只检查已经发生的变化是否漏写，不判断阶段完成，不总结或开启下一阶段；已发布的 0.1.2 仍使用单元笔记规则。本地 Hook 检查只能验证指令投递，真实教学与落盘仍需会话验收。目标宿主为 DSH 0.2.2-rc.1，Cordis 4.1.0。

插件不直接修改学习档案。学习记录、能力判断和成果沉淀依赖原 Agent 遵循规则并实际执行文件操作；本地 Hook 和消息协议测试通过，不等于真实教学效果已经验证。
