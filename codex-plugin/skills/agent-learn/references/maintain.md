# 轮次结束检查与学习资料维护

本规则用于正常学习后的补漏，也适用于显式维护。依据同目录 [原则](principles.md) 与 [规格](spec.md)，利用原 Agent 当前上下文处理，不创建评估 Agent，不重新授课。

## 先筛选，再读取

普通非学习任务、用户本轮要求不记录、没有实质变化，或本轮已完成同等维护时直接结束。Hook 提醒不等于模块结束，不要求每轮写文件、生成检查报告或补一道题。

先从当前对话判断是否出现：

- 当前主线、实际焦点、需要接续的支线或返回位置变化；
- 支线已足够支持当前用途，应移出活跃范围；
- 新的表现证据、明确误解、未解决缺口或原有记录失准；
- 一个阶段已经形成可独立理解和复用的认识、案例或正式评测结果；
- 一个教学单元已收束，核心问题已讲清且准备转向下一单元，即使尚无独立应用证据；
- 用户暂停、转向，或下一动作和接续线索已失效。

没有这些变化则结束；存在变化才从已确认工作区的索引定位相关领域，读取目标文件最新内容。不扫描所有领域，不从维护 Hook 自动初始化或扩展学习范围。

## 分别判断三类辅助工作

| 对象 | 动作与边界 |
| --- | --- |
| 当前状态 | 更新真实主线、当前焦点、必要支线、返回位置、证据与具体缺口。维护当前快照，不逐轮追加日志。 |
| 阶段判断 | 内部决定补充、检验、沉淀、接续或暂停是否合适；需要跨会话时保留简短依据和一个优先动作，不生成课程调度报告。 |
| 学习成果 | 单元收束时更新已有主题笔记，缺少主题笔记则新建简短笔记；保存核心问题、可复用的解释或操作、适用条件、边界与来源，不复制整段聊天。未验证的能力如实标注；正式评测只记录已发生的表现，不虚构分数和作答。 |

单元收束是笔记触发条件，不要求整个课程完成或先通过测评。若本轮从已讲完的单元转向下一单元，只更新进度或索引还不算完成维护：检查该主题是否已有可独立查阅的笔记，没有就创建，并把直接父索引链接到它。已有主题笔记则补充本轮新增的认识，避免重复。暂时暂停、零散答疑、仍在探索的单元和用户明确不记录的轮次可只维护必要接续状态。

支线结束时从活跃列表移除，仍有价值的认识、证据或缺口移到对应段落或主题笔记，保留链接。不要删掉成果，也不为了留历史另建无限增长的已完成列表。

讲过、自述理解、提示后完成和独立应用分别记录。现有能力证据不足可注明未知，不为填状态而考试，也不因用户说“懂了”就宣称掌握。

## 执行权限与修改方式

显式启用的学习工作区允许根据实际变化直接维护当前进度和有价值的学习成果，必要时创建局部笔记并更新直接父索引，无需反复问是否记录。读取目标最新内容后做最小修改，回读确认写入和导航；原文仍准确则不改。

用户改变长期目标时依据明确表达更新计划；AI 提出的新方向只作为建议，不擅自把临时兴趣升级为长期计划。删除、迁移或重组重要资料、扩大工作区范围及覆盖长期约定需要用户决定。无明确路径时不猜测；无修改权限或写入失败时说明未完成，保留已有资料，不反复重试。

不得修改插件源码、默认规则或 Codex 配置。不得提交 Git、安装插件、清理无关文件或把项目开发 Docs 当学习记录。

## 检查结束

无需修改时直接结束；完成维护最多简短说明有意义的记录结果，不重复已经讲过的课程或整份进度。

用户需要作答时保持等待；需要暂停时记录接续点；本轮还有未决重要取舍则简短指出，其他工作到此为止。仅因结束 Hook 被唤醒，不开启下一课、不新增考试、不再次初始化、不自行请求同轮续接。
